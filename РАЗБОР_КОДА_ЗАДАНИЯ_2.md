# Разбор кода задания 2: что, где и почему

Файл предназначен для пофайловой ревизии проекта: назначение модулей, ключевые
функции, инварианты, критерии, тонкие места и список кандидатов на чистку.
Читать параллельно с кодом; тесты можно гонять `bash run.sh test` (без сети).

## 1. Карта репозитория

```
.
├── run.sh                     воспроизводимый запуск одной командой (uv или venv+pip)
├── Makefile                   краткие цели поверх uv
├── pyproject.toml             зависимости + extras (gigachat, test, rerank, bm25)
├── .env.example               шаблон конфигурации (без секретов)
├── main.py                    консольный диалог (живой GigaChat)
├── src/
│   ├── config.py              реестр зависимостей (Singleton, подменяется в тестах)
│   ├── models.py              слоты (structured output), политики, артефакты
│   ├── llm.py                 GigaChat, эмбеддеры, HashEmbedder, системный промпт
│   ├── context.py             бюджет токенов + суммаризация
│   ├── kb/                    каталог документов (catalog, seeds)
│   ├── rag/                   гибридный поиск (lexical, dense, fusion, service, tool)
│   ├── memory/                память пользователя (schema, store, consolidation)
│   └── graph/                 сборка и узлы диалогового графа (build, nodes)
├── scenarios/
│   ├── dialogs.py             генератор длинных диалогов (по 33 реплики пользователя)
│   └── params.py              офлайн-«суммаризатор»/аккумулятор ключевых фактов
├── scripts/
│   ├── demo_temporal.py       критерий 4 (редакции по датам)
│   ├── demo_budget.py         критерий 2 (бюджет/суммаризация)
│   ├── demo_memory.py         критерии 5-6 (память, аудит, удаление, консолидация)
│   └── consolidate.py         фоновая переработка памяти вне диалога
└── tests/                     офлайн-тесты без сети и без ключей
```

## 2. Поток данных одного хода диалога

```
пользователь -> extract_slots (structured output) 
   -> manage_context (счёт токенов, при переполнении: summarize + trim)
   -> build_profile (поиск фактов пользователя с recency-весом)
   -> respond (GigaChat.bind_tools([search_knowledge]);
        цикл: если есть tool_calls -> исполняем инструмент -> возвращаем ToolMessage
        -> ответ модели обязан содержать ссылку [NN-Б vN])
   -> persist_user (слоты профиля -> MemoryEngine.write; зеркало в LangGraph Store)
```

## 3. Пофайловый разбор

### src/config.py — реестр зависимостей
- `Settings` — значения из env (модели, бюджеты, as_of, `MEMORY_FILE`).
- `Deps` — живые объекты (llm, extractor, embedder, kb, memory, store, budget).
  Паттерн повторяет шаблон задания 3 (глобальные провайдеры), позволяя тестам
  подменять компоненты без моков сетевых вызовов.
- `configure / reset_defaults` — точки подстановки. **Инвариант**: узлы графа
  читают только через `deps`.

### src/models.py — слоты и артефакты
- `SlotUpdate` (pydantic) — structured output: по одному вызову модели заполняются
  известные поля, остальные остаются None.
- `SlotNames/ALL_SLOTS/slot_policies` — таксономия и разметка «слот -> профиль».
- `CitedSource`, `DialogTurn` — артефакты (источники, журнал бюджета).

### src/llm.py
- `get_chat_llm()` — живой `ChatGigaChat` (ленивый импорт, чтобы тесты не зависели
  от пакета и ключей).
- `build_extractor(llm)` — `with_structured_output(SlotUpdate)`.
- `Embedder` (protocol) + `HashEmbedder` — детерминированный офлайн-эмбеддер
  (sign-hashing по словам); `get_embeddings()` выбирает GigaChat либо заменитель.
- `SYSTEM_GUIDE` — правила поведения (обязательность `search_knowledge` и ссылки).

### src/context.py — критерий 2
- `count_tokens_approx` — оценка chars/4.6 (фолбэк без модели).
- `actual_usage_tokens` — реальные токены ответа из `usage_metadata`.
- `RollingSummaryPipeline.run(history)`:
  если оценка истории <= бюджет -> action none;
  иначе вытесняем старейшие сообщения и сворачиваем их `summarizer` (задача-спец.
  промпт или офлайн-аккумулятор); маркер сводки вставляется в начало окна;
  результат возвращается в `state.messages` (узлу `respond`).
- `default_summarizer(llm)` — живая свёртка GigaChat по `SUMMARY_PROMPT`.

### src/kb/ — база знаний
- `catalog.py`: `Edition` (version/valid_from/valid_to/text),
  `KnowledgeDoc.edition_on(date)` — выбор редакции на момент времени,
  `Catalog.all_active_texts(date)`, `catalog_registry`.
- `seeds.py`: 16 семейств, 26 редакций; временные расхождения для критерия 4
  (Start 06-Т, API 02-Т, инциденты 01-РЕ, окна 17-О, биллинг 05-Б, алерты 20-Р).

### src/rag/ — критерии 3 и 4
- `lexical.py`: компактный Okapi BM25 + `boost_exact_identifiers` — поднимает
  документ, чей номер (`06-Т`) встретился в запросе (точный идентификатор).
- `dense.py`: numpy-матрица нормализованных эмбеддингов, косинусный поиск.
- `fusion.py`: `reciprocal_rank_fusion`, `IdentityReranker`, `CrossEncoderReranker`
  (опциональный, лениво импортируется).
- `service.py`: `HybridSearch` — снимки индексов по `as_of`; `search()` =
  фильтр по дате -> lex + dense -> RRF -> реранк -> `Hit` с `passage_text()`.
- `tool.py`: `search_knowledge` — именно то, что агент вызывает сам (не фикс. цепочка).

### src/memory/ — критерии 5 и 6
- `schema.py`: `MemoryKind` + `RETENTION_DAYS[kind]` (разные горизонты),
  иерархия доверия `TRUST_ORDER`, `MemoryRecord`, `AuditEntry`.
- `store.py`: `MemoryEngine`
  - `write()` — ADD / REFRESH / UPDATE / REJECT по правилу доверия;
  - `delete()` — PURGE немандаторных, MASK мандаторных (платёжные записи),
    аудит обеих операций;
  - `search()` — семантика x recency (свежесть);
  - снимок в JSON между перезапусками (`save/_load`, автосохранение).
- `consolidation.py`: отдельный скомпилированный StateGraph (collect ->
  merge_duplicates -> build_summary -> stats), запускается скриптом вне диалога.

### src/graph/ — критерий 1
- `build.py`: `AgentState`, пять узлов, `compile(checkpointer=MemorySaver(),
  store=...)`, `run_config`, `bootstrap`.
- `nodes.py`: `extract_slots`, `manage_context`, `build_profile`, `respond`
  (внутренний цикл инструментов), `persist_user`.

### main.py и скрипты
- `main.py`: интерактивный цикл; печатает артефакт сессии (слоты, ссылки, бюджет).
- `scripts/demo_*.py`: замкнутые офлайн-демонстрации критериев для скринкаста.

### tests/ (без сети)
- `conftest.py`: автозачистка реестра + фикстура `offline_env`.
- `fakes.py`: `ScriptedChatModel` (выдаёт script по очереди), `FakeExtractor`.
- накрывают: контур (1), бюджет/суммаризацию (2), гибрид (3), редакции (4),
  память (5-6), длинные диалоги (сценарии).

## 5. Тонкие места и компромиссы (проверить руками)

1. **Cite-контроль** закреплён в SYSTEM_GUIDE (обязательная ссылка [NN-Б vN])
   и проверяется в тесте контура; в живом контуре жёсткого re-check последнего
   ответа нет — при желании можно добавить валидацию.
2. **manage_context** вызывает суммаризатор синхронно внутри async-узла; для
   живого режима приемлемо, для нагрузки лучше вынести в отдельный поток.
3. `search()` памяти при `embedder=None` подставляет константную близость —
   это явный фолбэк, документирован в докстринге.
4. Хранилища в памяти процесса; между перезапусками долговременная память
   сохраняется только через `MEMORY_FILE`.
5. Гипотеза бюджета адаптивна в демо (доля от полной истории) — удобно для
   скринкаста, но в живом контуре размер бюджета берётся из env.
6. Ответственность офлайн-онлайн: `HashEmbedder` и компактный BM25 (без
   стеммера pymorphy3) грубее, чем bm25s+GigaChat — улучшения в roadmap.

## 6. Рефакторинг (выполнен)

- удалены мёртвый класс `HistoryWindow` и неиспользуемый параметр `logger`;
- удалены неиспользуемые импорты: `tokenize`/`field` (service), `Iterator` (store),
  `Optional` (schema), `MemoryRecord` (consolidation), `SLOT_FIELD_LABELS` и неиспользуемое
  связывание `exc` (llm), `bisect`/`field` (catalog), `field` (config),
  `TURN_SEPARATOR` (test_context_budget);
- поле `_Snapshot.rows` убрано (не заполнялось);
- слияние RRF унифицировано: локальная `reciprocal_rank_fusion_sorted` удалена,
  сервис использует каноническую `fusion.reciprocal_rank_fusion(..., k=620)`;
- пустая функция `_dated_index` в каталоге удалена;
- удалены неиспользуемые: модуль `observability.py`, константы
  `DEMO_QUERY_*` (отчёт/уведомления/API/инцидент), `ALL_SLOTS`,
  `SLOT_FIELD_LABELS`, `HORIZON_LABELS`, `DEDUP_THRESHOLD`, `SEMANTIC_WINDOW`,
  поля `consolidate_min_age_days` и `deps.tracer`, функции `hits_to_citations`,
  `citation_tags`, `assert_cited`, `offline_reset`, константа `OFFLINE_TODAY`;

Остались намеренные side-effect импорты (pyflakes их показывает как unused, это норма):
`import src.kb.seeds` в `src/kb/__init__.py`, `tests/conftest.py`,
`scripts/demo_temporal.py` и алиасы `as S` в `test_kb_temporal.py`,
`test_hybrid_search.py` — они выполняют регистрацию документов БЗ при импорте.
Проверка чистоты: `uv run --with pyflakes -- python -m pyflakes src scenarios scripts main.py tests`.

## 7. План проверки для студента

1. `bash run.sh test` — все офлайн-тесты зелёные.
2. `bash run.sh demo-temporal` — разные редакции на разные даты.
3. `bash run.sh demo-budget` — срабатывание суммаризации и сохранность фактов.
4. `bash run.sh demo-memory` — память, аудит, удаление, консолидация.
5. `bash run.sh run` — живой диалог (нужны GIGACHAT_CREDENTIALS).
6. Перезапуск с `MEMORY_FILE`: слоты/факты восстановлены из снимка.
