# Сопроводительный текст к заданию 2
## «Диалоговый агент с памятью и гибридным поиском»

### 1. Задача

Построен диалоговый агент поддержки дев-облачной платформы на стеке
**GigaChat + LangGraph**. Пользователь ведёт длинный диалог (по 33 реплики в
сгенерированных сценариях), сообщая реквизиты по частям, перебивая себя
посторонними вопросами и возвращаясь к теме. Агент:

- собирает структурированный набор слотов (structured output);
- ищет документы в базе знаний и отвечает строго со ссылкой на источник;
- накапливает долговременные сведения о пользователе, которые переживают
  завершение сессии и даже перезапуск приложения (JSON-снимок).

### 2. Предметная область и база знаний

База знаний имитирует нормативную базу платформы и состоит из **16 семейств
документов / 26 редакций** (`src/kb/seeds.py`). У ряда документов редакции
различаются по датам, поэтому один и тот же вопрос на разную дату даёт разные
корректные ответы (критерий 4).

Примеры временных расхождений:

- тариф Start: лимит воркеров 5 -> 10 с 15.01.2026 (док 06-Т);
- лимиты API: Pro 600 -> 900 req/min с 01.04.2026 (док 02-Т);
- реакция на критический инцидент: 15 -> 5 минут с 01.03.2026 (док 01-РЕ);
- окна обслуживания, каналы алертов, ставка сверхлимитных часов.

Точный поиск по служебному номеру (`06-Т`, `11-Т`) обеспечивает лексический
канал поиска; смысловой канал — эмбеддинги.

### 3. Архитектура

Линейный контур LangGraph (узлы `src/graph/nodes.py`):

```
user message
 -> extract_slots    (structured output, слоты копятся в state)
 -> manage_context   (бюджет токенов + суммаризация выпавшего окна)
 -> build_profile    (долговременная память пользователя, recency-взвешивание)
 -> respond          (LLM + инструмент search_knowledge, ответ со ссылкой)
 -> persist_user     (новые слоты -> память + зеркало в LangGraph Store)
```

Кратко по модулям:

| Модуль | Назначение |
|---|---|
| `src/models.py` | схема слотов, политики, типы артефактов |
| `src/context.py` | бюджет токенов, суммаризация (фактические токены из usage_metadata) |
| `src/rag/` | гибридный поиск: BM25 + эмбеддинги + RRF + реранк, `@tool` |
| `src/kb/` | каталог документов с редакциями и периодами действия |
| `src/memory/` | память пользователя: схема, горизонты, конфликты, аудит, удаление, recency, консолидация |
| `src/graph/` | сборка и узлы диалогового графа |
| `src/llm.py` | интерфейсы GigaChat и эмбеддеров (+ офлайн-заменитель HashEmbedder) |
| `src/config.py` | реестр зависимостей (для подмены в тестах) |

### 4. Соответствие обязательным критериям

| № | Критерий | Реализация | Проверка |
|---|---|---|---|
| 1 | Контур LangGraph: слоты, checkpointer, Store, ссылка на источник | `src/graph/*`, `src/models.py` | `tests/test_graph_contour.py` |
| 2 | Бюджет токенов (фактические) + суммаризация спец-промптом | `src/context.py` | `tests/test_context_budget.py`, `tests/test_summarization_scenarios.py` |

### 5. Запуск и проверка

```bash
bash run.sh test            # venv + зависимости + офлайн-тесты (33 теста)
bash run.sh demo-temporal   # критерий 4
bash run.sh demo-budget     # критерий 2 (бюджет/суммаризация)
bash run.sh demo-memory     # критерии 5-6
bash run.sh run             # живой диалог (требует GIGACHAT_CREDENTIALS в .env)
```

Тесты выполняются без сети и без ключей: модель заменяется дублем
(`tests/fakes.py`), эмбеддеры — детерминированным `HashEmbedder`.

### 6. Ограничения и допущения

- кратковременная (checkpointer) и долговременная память живут в памяти
  процесса; между перезапусками долговременная сохраняется через
  `MEMORY_FILE=memory_dump.json`;
- офлайн-режим использует `HashEmbedder` и компактный BM25 — живой режим
  переключается на `GigaChatEmbeddings`;
- реранкер cross-encoder подключается опционально (экстра `rerank`);
- диалоги для демонстрации синтетические, сгенерированы генератором по мотивам
  `dialogs.jsonl`.

### 7. Вывод

Решение закрывает все шесть обязательных критериев задания 2 кодом и
автотестами, сопровождается базами знаний с редакциями, офлайн- и онлайн-демо,
единым скриптом запуска и подготовлено к скринкасту.
